# 长上下文的存储与通信边界，比单个算子峰值更值得验收

**覆盖窗口：**2026年11月22日08:47至11月25日08:47（Europe/Zurich，UTC+1；检索截止08:47）。优先检查最近24小时；因一手材料主要只标发布日期，保守扩展至72小时。今天的线索分别指向外部 KV 存储放大、腾讯模型投影融合和 Intel 混合并行通信。前两项揭示容量与吞吐不能混为一谈，后一项提醒跨并行维度的可靠性要进入系统验收。近期国内厂商官方渠道未发现可核实且未重复的重大硬件发布；国内工作负载由 DeepSeek 与腾讯模型的原始社区材料覆盖。

## 1. DeepSeek 长上下文外部 KV 存储：CP8 的重复写入可达 15.7 倍

SGLang 社区11月24日[提案](https://github.com/sgl-project/sglang/issues/52732)给出 DeepSeek-V4.1-Flash 在8张 H20、TP8/EP8/CP8、32,768 token 前缀和 Mooncake direct linker 下的复现：外部存储占用从840,089,600字节，降到所提共享与 SWA replay 路径的53,493,760字节。原路径按 CP rank 分别写入等价的压缩 KV 与 indexer 页，另有不宜直接共享的 rank-local SWA 页。前后相差约15.7倍，但后者仍是提案及作者测试，不是已发布的通用优化。

这是存储所有权与布局问题，不能把93.63%的外部占用下降当成 TTFT 或解码加速；作者的独立恢复夹具还显示读取字节没有下降。对昇腾超节点的启示是按模型 KV 池逐一核对 CP/TP 分片后哪些页真可共享、哪些必须保留 rank-local 语义。若现有部署没有 CP 或外部 KV 层，此收益不适用；迁移还涉及缓存键版本、恢复顺序、通信与正确性测试。

建议固定同一 DeepSeek 工作负载、精度、CP 宽度和长前缀复用率，对照现有布局与按池共享方案，分别测外部物理字节/逻辑 token、恢复后 token 一致率、TTFT、P99 和适配工时。若容量收益伴随恢复时延或跨节点通信恶化到违反 SLO，就不应按容量指标单独推进。

## 2. 腾讯 Hy4 Flash 投影融合：核函数收益大，端到端增益有限

vLLM 社区11月25日[开放 PR](https://github.com/vllm-project/vllm/pull/69783)，把 Hy4 Flash 每层的 Q 与 KV 下投影合成一次 GEMM。作者在单张 H100、真实 BF16 权重、单 token 的微基准中测得12.67微秒降至7.25微秒，约1.75倍；4张 H100 80GB、TP4、官方 FP8 checkpoint、BF16 激活、每请求8192输入/1024输出 token 下，六档并发的输出吞吐中位数增幅为1.85%—3.65%。推测解码、异步调度和前缀缓存均关闭。

这说明减少小 GEMM 启动和访存可有效，但全服务受其他层、调度与通信稀释。作者报告并发16的两轮成对测试一正一负，最终改动后的完整六档结果仍待验证。昇腾可核对 Hy4 类模型是否已有等效融合；若需新增 CANN 算子或权重重排，还要计入编译、加载、动态 batch 和精度回归成本。不能把 H100 数字转写为 NPU 增益。

建议选同一 checkpoint 和真实请求长度分布，在等质量约束下比较融合前后 TTFT、TPOT、P99、有效 token/秒、显存峰值及适配工时；以多个并发档位重复运行。若端到端增益低于测量波动或增加启动成本，则优先处理更大的瓶颈。

## 3. Intel 混合并行停滞：跨通信组调度可能压倒算子优化

SGLang 社区11月24日[复现](https://github.com/sgl-project/sglang/issues/52883)：4张 Intel CRI GPU 上，Llama-3.1-8B-Instruct 的 TP2×PP2 测试停滞或报 DEVICE_LOST，TP4 与 PP2 单独通过，同一测试在 Arc Pro B60 也通过。报告者用纯 `torch.distributed`/XCCL 脚本复现 TP all-reduce 排队后发布 PP `irecv` 的模式；设备分析里 all-reduce 约慢6.6倍，在接收前主机同步可消除停滞。原因仍被报告者定位为 oneCCL、Level Zero 或驱动层的待查问题，不能归为通用 SGLang 缺陷。

昇腾的直接动作不是推断存在同一问题，而是把 TP、PP 与 EP 混用时的通信顺序纳入超节点验收。同步规避可能牺牲重叠与吞吐；跨后端迁移还涉及通信组、流语义和故障恢复适配。建议在固定模型及并行规模下交错提交集合通信与点对点收发，记录挂起率、P99、每层通信时间和同步前后有效吞吐；若串行化才稳定，应先解决调度或通信依赖，再宣称系统扩展收益。

## 今日验证优先级

1. 长上下文 CP 与外部 KV 组合先审计物理占用、恢复正确性和 TTFT，明确可共享池。
2. Hy4 类投影融合用多并发端到端对照确定真实收益及适配工时。
3. 混合并行通信压测把挂起率与 P99 列为上线门槛。
